# Requirements Review Skill

## 目的

実装前に、要件の不足、曖昧さ、権限上の問題を検出します。

要件が未確定のまま実装へ進まないことを目的とします。

## 入力

次の情報を受け取ります。

- 対象機能
- 対象利用者
- 業務上の目的
- 入力項目
- 出力または画面表示
- 保存先
- 権限
- 正常時動作
- 失敗時動作
- 受入条件

不足している情報を推測で確定しません。

## 確認する6項目

1. 誰が使う機能か
2. 何を入力、閲覧、更新するか
3. 正常時に何が起きるか
4. 失敗時に何を表示するか
5. 誰に閲覧、編集権限があるか
6. 完了を何によって判定するか

## 追加確認

次の条件も確認します。

- 個人情報を開発fixtureに含めない
- 実データを前提にしない
- 未入力と0を区別する
- 取得失敗を空データとして扱わない
- 保存失敗を成功として表示しない
- 事業所間のデータ分離を定義する

## 判定

次のいずれかが未確定の場合は`HOLD`です。

- 対象利用者
- 保存先
- 権限
- 失敗時動作
- 受入条件

画面モックまたは合成fixtureによる検証だけを行う場合は、実装範囲を明示したうえで条件付き`READY`にできます。

## 出力形式

```text
要件判定: READY / HOLD

対象利用者:
対象業務:
入力:
出力:
保存先:
権限:
正常時動作:
失敗時動作:
監査対象:
未確定事項:
受入条件:
実装可能範囲:
```

## 出力上の規則

- 根拠のない補完をしない
- 未確認事項を`未確定事項`へ残す
- `READY`と`HOLD`の理由を明示する
- 実装可能範囲と実装禁止範囲を分ける
- 本番公開または実データ利用を自動的に許可しない
