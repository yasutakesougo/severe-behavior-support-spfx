# requirements-review

## 目的

実装前に、要件の不足、曖昧さ、権限上の問題、検証可能性を検出します。

要件が未確定のまま設計・実装へ進まないことを目的とします。

## 使用する場面

- 新規機能の要件整理直後
- Logical Command `new-feature` 起動時
- 実装計画作成前の要件確定確認

## 入力

- 対象機能
- 対象利用者
- 業務上の目的
- 入力項目
- 出力または画面表示
- 保存先
- 権限
- 正常時動作
- 失敗時動作
- 受入条件
- 対象 Issue / 要件メモ

## 前提条件

- 対象機能または対象 Issue が識別できる
- 不足情報を推測で埋めない方針が共有されている
- `docs/process/ai-role.md` の Scope / Out of Scope を参照できる
- 共通 Authority は `.agents/skills/_shared/authority-boundaries.md` を参照する

## 実行手順

1. 対象機能と対象利用者を固定する
2. 入力・出力・保存先を列挙する
3. 権限（閲覧・編集）を確認する
4. 正常時動作と失敗時動作を確認する
5. 受入条件を確認する
6. 個人情報・実データ前提・事業所間分離を確認する
7. 未確定事項を HOLD として列挙する
8. 実装可能範囲と実装禁止範囲を分離する
9. 判定を出す

## 確認項目

- 誰が使う機能か
- 何を入力、閲覧、更新するか
- 正常時に何が起きるか
- 失敗時に何を表示するか
- 誰に閲覧、編集権限があるか
- 完了を何によって判定するか
- 個人情報を開発 fixture に含めていないか
- 実データを前提にしていないか
- 未入力と 0 を区別しているか
- 取得失敗を空データとして扱っていないか
- 保存失敗を成功として表示していないか
- 事業所間のデータ分離が定義されているか

## 停止条件

- 対象利用者が未確定
- 保存先が未確定
- 権限が未確定
- 失敗時動作が未確定
- 受入条件が未確定
- Out of Scope（本番 SharePoint / Entra / M365 / 本番データ変更）が工程に含まれる

## 判定基準

- `PASS`: この Skill では原則使用しない。Gate 通過判定が必要な場合は後続 Skill で扱う
- `READY`: 6 項目と追加確認が揃い、実装可能範囲が明示されている
- `HOLD`: 対象利用者・保存先・権限・失敗時動作・受入条件のいずれかが未確定、または要件確定そのものに必要な承認・Decision 待ち
- `FAIL`: P0 または P1 相当の要件欠陥があり、設計へ進めない。P2 は記録のうえで後続 Issue に送れる
- `NOT APPLICABLE`: 要件整理を要しない相談・文書整理のみの作業

## 成果物

- 要件判定
- 対象利用者 / 対象業務
- 入力 / 出力 / 保存先 / 権限
- 正常時動作 / 失敗時動作
- 監査対象
- 未確定事項
- 受入条件
- 実装可能範囲 / 実装禁止範囲
- Findings（P0 / P1 / P2）

## 禁止事項

共通の merge / deploy / production / tenant mutation 境界は `.agents/skills/_shared/authority-boundaries.md` に従う。

本 Skill 固有の禁止事項:

- 未確認事項を推測で確定すること
- `HOLD` を `PASS` / `READY` と同義に扱うこと
- 根拠のない補完で要件を確定すること
- 本番公開または実データ利用を要件レビューだけで許可すること
- 後続の Merge / Deploy approval が未取得であることだけを理由に要件レビューを停止すること
