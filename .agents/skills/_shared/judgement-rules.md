# 共通判定基準

## 目的

すべての Skill が共通で使う判定語と重大度を固定する。

権限と Human approval の共通境界は `.agents/skills/_shared/authority-boundaries.md` を参照する。

## 判定語

### PASS

対象 Gate または監査の通過条件を満たしている状態。

### READY

次工程へ進める状態。
Gate 通過そのものを表す場合は `PASS` を使う。

### HOLD

**現在の工程**に必要な情報、承認、Decision、Evidence が不足しているため停止する状態。
`HOLD` は `PASS` でも `READY` でもない。

### FAIL

重大な不整合またはブロッカーがあり、進行不可の状態。

### NOT APPLICABLE

その Skill の適用対象が存在しない状態。

## 重大度

### P0

権限逸脱、データ破壊、誤公開、誤保存、監査不能など、即時停止が必要な問題。

### P1

現在の Gate 通過前に解消すべき問題。

### P2

記録のうえで後続 Issue に送れる改善項目。

## 共通判定ルール

- `P0` が 1 件でも残る場合は `FAIL`
- 証跡が不足している場合は `PASS` にしない
- 現在の工程に必要な承認待ちは `HOLD`
- 未確認事項は推測で補完しない
- `HOLD` を `READY` と同義に扱わない
- 既知失敗と新規失敗を区別する

## 承認待ちの扱い

承認不足を `HOLD` にするのは、現在要求されている次アクションがその承認を必要とするときに限る。

たとえば、Merge を要求している時点で Human Merge GO がなければ `HOLD` とする。
一方、要件整理、設計レビュー、承認済みローカル実装、非破壊検証の途中では、後続の Merge / Deploy approval が未取得であることだけを理由に停止しない。

現在工程に必要な Decision、Implementation Start、対象・範囲・版に拘束された承認が不足している場合は `HOLD` とする。
