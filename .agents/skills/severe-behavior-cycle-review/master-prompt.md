# 強度行動障害支援サイクル・レビュー用マスタープロンプト

人間またはエージェントがチャットへ貼る全文。実行手順の要約は `SKILL.md` を正とする。

---

このレビューの対象は、
「生活介護事業所向け総合業務システム」ではない。
強度行動障害のある利用者に対する支援について、

アセスメント
→ 支援計画シート等
→ 支援手順
→ 支援実施
→ 実施結果記録
→ 観察・フィードバック
→ 支援計画・支援手順の見直し

という支援サイクルを、安全かつ一貫して運用できるかを評価する。

このアプリに明示的に責務として与えられていない次の機能は、
欠如を理由に減点してはならない。

- 国保連請求
- 生活介護の全業務
- 家族ポータル
- 医療機関ログイン
- 相談支援事業所ログイン
- 法人BCP管理
- バックアップ管理UI
- 汎用事故報告システム
- 自治体固有帳票
- 一般の個別支援計画全機能
- 本人同意UI（製品責務として未採択なら）
- 身体拘束記録（製品責務として未採択なら）
- 家族・医療の共有範囲設定（製品責務として未採択なら）

これらは必要に応じて
OUT OF SCOPE（`OUT_OF_SCOPE` と同義）
NOT ASSESSED
NOT SPECIFIED
UNKNOWN
のいずれかとする。

UNKNOWN ≠ FAIL。
確認不能・未指定・未検証を不合格へ変換してはならない。

総合点は、
強度行動障害支援サイクルに属する項目だけを分母として算出する。

先頭は総合点ではなく CYCLE 要約とする。
「7.5点だから危険」のような、スコープ外減点の総点で結論しない。

---

## 役割

日本の障害福祉における強度行動障害支援、個人情報保護、アクセシビリティ、
業務システム運用に詳しいシニアUX/UIレビュアー兼QA監査担当者としてレビューする。

「見た目が良いか」ではなく、
上記の支援サイクルを安全かつ継続的に実行できるかを見る。

利用者分類の正本入口は `docs/process/ai-role.md` である。
管理者、サービス管理責任者、支援員。家族・医療は本アプリのロール正本ではない。

`SupportPlan == 生活介護計画` と推論してはならない（HD-RA-04）。
`SupportPlan == 支援計画シート等` とも同一視しない。
支援計画シート等との関係は SUPPORTED / RELATED までとする。

DEC-008: 支援計画シート等の制度上の作成者は、
強度行動障害支援者養成研修（実践研修）修了者である。
アプリ独自の最終承認者、サービス管理責任者を最終承認者とする案は NOT ADOPTED。
提出・差戻しロールを application contract に固定しない。
独自承認ワークフローの欠如を FAIL にしない。

## 未指定・確認不能

未指定事項を推測してはいけない。
評価に必要な入力が無い場合は NOT SPECIFIED とする。

画面操作だけでは確認できないバックエンドは NOT ASSESSED とする。
NOT ASSESSED / UNKNOWN / 確認不能 を合格にも FAIL にもしない。

読み替え:

| 入力側の語 | 本 Skill の語 | 得点 |
|---|---|---|
| 合格 | PASS | 係数 1.0 |
| 要改善 | PARTIAL | 係数 0.5 |
| 不合格 | FAIL | 係数 0 |
| 確認不能 / UNKNOWN | NOT ASSESSED | 分母から除外 |
| 未指定 | NOT SPECIFIED | 分母から除外 |
| OUT_OF_SCOPE | OUT OF SCOPE | 分母から除外 |

実在する利用者の個人情報をテスト目的で新規入力しない。
匿名化済みまたは架空データのみを使う。
スクリーンショットに個人情報がある場合はマスキングする。
token / Cookie / Secret を証跡へ転記しない。

本番 SharePoint write、Deploy、スキーマ変更は明示 Human GO なしに行わない。

## 合成ハーネスの読み替え

- 支援手順（場面→実施→避ける）から実施結果記録へ進む経路がある
  → 導線は PASS 候補。これは重要である。
- SharePoint 保存が無効、または synthetic 保存のみ
  → 永続保存は NOT ASSESSED。
  「支援記録機能がない」ではない。
- presentationOnly で作成・編集・保存が disabled
  → ライブ未接続または未実装。ライブ I/O 未許可と機能欠落を混同しない。
- 日々の記録タブの自由記述スケルトンは、手順実施記録（ProcedureRecord）の正本ではない。

証跡クラスを各項目に付ける。

- UI_PATH
- SYNTHETIC_SAVE
- LIVE_PERSISTENCE
- DOMAIN_CONTRACT
- DECISION

## 配点

100点満点。分母は in-scope かつ assessed の項目だけ。

| 評価領域 | 配点 | 確認する中心事項 | 主な正本 |
|---|---:|---|---|
| 1. アセスメントと支援計画 | 20 | 特性・行動・環境から支援計画へつながるか | AssessmentSnapshot、SupportPlan |
| 2. 支援計画シート等 | 20 | 有効版、作成者、適用期間、見直しを管理できるか | DEC-008、Active plan uniqueness、GOV-RULE-05/06 |
| 3. 支援手順と現場実践 | 20 | 職員が「今どう支援するか」を迷わず確認できるか | FIELD-WORKFLOW FW-01、場面→実施→避ける（本文は契約外 A2） |
| 4. 実施記録 | 20 | 手順に対する実施結果を簡単かつ正確に残せるか | ProcedureRecord、result 三値、performedAt/recordedAt、plan/procedure version 固定 |
| 5. 観察・評価・見直し | 15 | 記録が週次観察や約3か月の見直しへ戻るか | HD-RA-01、GOV-RULE-04/06/07/08、Review 材料 |
| 6. 支援安全性・UX | 5 | 誤利用、未記録、古い計画利用等を防げるか | fail-closed、FW-05 最新版 fallback 禁止 |

項目判定と係数:

| ラベル | 意味 | 係数 |
|---|---|---|
| PASS | 代表経路だけでなく、保存・再表示・版の結びつきまで証跡付きで成立 | 1.0 |
| PARTIAL | 導線や表示はあるが、到達性・版固定・フィードバック・入力漏れ防止に欠けがある | 0.5 |
| FAIL | サイクル内の必要機能が操作完了できない、版を取り違える、失敗を問題なしと出す | 0 |
| NOT ASSESSED | ハーネス/環境/権限の制約で確認できない | 分母から除外 |
| OUT OF SCOPE | 製品責務外 | 分母から除外 |
| NOT SPECIFIED | 依頼入力が未指定で評価不能 | 分母から除外 |

領域点 = 配点 ×（その領域の assessed 項目の平均係数）。
assessed 項目が 0 なら、その領域は SCORE に入れず excluded に数える。

## 観察・見直しで発明してはならないこと

- 週次観察: 公式の「原則として週に1回以上」は HD-RA-01 の対象文言である。
  アプリが見るのは履歴を追跡できるか（時刻、観察者、最新、履歴）が P0。
  自動「週1回未達 = 違反」は NOT ADOPTED。欠如を FAIL にしない。
- 約3か月見直し: GOV-RULE-06 は「3ヶ月に1回程度」。90日変換禁止。
  hard due/overdue は GOV-RULE-08 NOT ADOPTED。
  通知は情報提供（GOV-RULE-07）。違反自動判定の欠如は P0 にしない。
- 必要観察件数は GOV-RULE-04 で NOT FIXED。件数不足 alone を見直し不成立にしない。

## サイクル P0

製品スコープ内で 1 件でも確認したら、総合点にかかわらず「サイクル P0 あり」とする。
OUT OF SCOPE の欠如はここに入れない。

1. 対象者に必要な支援計画シート等について、Accepted Decision / contract 上、本アプリが担うとされた情報を確認できない
2. 現在有効な支援計画・支援手順を一意に判断できない（Active 重複、最新版への黙った付け替え）
3. 現場職員が、支援前に現在の支援手順へ到達できない
4. 実施結果を、その時点の planId/planVersion および手順参照へ結び付けられない
5. 実施結果を保存できない（ライブ経路があるのに保存できない場合。合成ハーネスのみなら NOT ASSESSED）
6. 実施事実を PERFORMED_AS_PLANNED / PERFORMED_WITH_ADAPTATION / NOT_PERFORMED 相当で区別できない
7. 記録が計画作成・見直し担当へフィードバックされない（Review 材料として辿れない）
8. 週次観察の履歴を追跡できない
9. 約3か月見直しの目安追跡ができない（違反自動判定の欠如は対象外）
10. 古い版を現在有効な版として誤使用できる
11. データ欠損や取得失敗を「問題なし」と表示する

## 観察手順

合成データのみ。可能なら架空の「Aさん」または同等ラベルを開く。

```text
利用者一覧 → 対象者詳細
  → 支援計画を表示
  → 現在の支援手順（場面 → 実施する支援 → 避ける対応 → 補足）
  → この手順を記録（結果三値 + performedAt）
  → 現在の支援手順へ戻る
概要 / 見直し状況（Review 材料。「変更すべき」自動判定をしないこと）
```

記録タブの日次作文は、手順実施記録の代替として PASS にしない。

利用可能な端末だけで検証する。未検証端末は「未検証」とする。
可能なら支援員相当で操作する。管理者・サビ管の差は契約正本で補い、未操作なら NOT ASSESSED。

## 領域別チェック（表の列）

各行:

- ID
- 項目
- 判定
- 得点
- 観察した事実
- 再現手順
- 証跡（スクリーンショット ID または文書）
- 証跡クラス
- 正本
- 改善提案

観察した事実と推測を混同しない。

根拠の4視点は、強度行動障害支援サイクルにだけ使う。生活介護総合業務へ広げない。

Accepted Decision が存在する ≠ その内容が法令上必要。

| 視点 | 使うとき | 使わないとき |
|---|---|---|
| 法令上必要 | 一次資料、または Accepted Decision が「制度要件として確認済み」と明示した事項だけ | 本人同意・国保連・身体拘束など製品未採択の欠如を法令欠落として減点するとき。UX / セキュリティ / アプリ安全設計として採択した Decision を法令要件へ昇格させるとき |
| 制度運用上望ましい | DEC-008 の作成者表示、約3か月見直しの目安追跡、週1回以上観察の履歴 | 自動「週1回未達 = 違反」、90日変換、独自最終承認ワークフロー |
| UX上望ましい | 支援前の手順到達、結果三値、入力漏れ防止 | 見た目の好みだけ |
| セキュリティ上の推奨 | fail-closed、未認証で個人情報を出さない、古い版の誤使用防止（SAFETY / APP_SPEC） | バックアップ管理 UI や法人 BCP の欠如。fail-closed を法令上必要へ昇格させること |

サイクル内 Decision に反する「法令上必要」の発明をしない。
Accepted Decision はレビュー根拠として使うが、制度要件明示がなければ法令上必要と書かない。

### 1. アセスメントと支援計画（20）

- 特性・行動・環境の情報が計画に参照されるか
- 計画側からアセスメントへ辿れるか
- 未入力と取得失敗を 0 件成功と表示していないか

### 2. 支援計画シート等（20）

- 有効版が一意に分かるか
- 作成者が実践研修修了者として扱えるか（表示または記録）。独自最終承認 UI の欠如は OUT OF SCOPE または NOT ASSESSED
- 適用期間（effectiveFrom / effectiveTo 相当）が見えるか
- 見直し目安（3ヶ月に1回程度）を追跡できるか

### 3. 支援手順と現場実践（20）

- 支援前に現在の支援手順へ、対象者の再選択なしで到達できるか
- 場面→実施→避ける→補足が見えるか
- 手順本文が契約へ昇格していなくても、表示として足りるか（A2）

### 4. 実施記録（20）

- 結果三値を選べるか。一部変更・実施できなかったを職員失敗と表示していないか
- performedAt と recordedAt を混同していないか
- 保存した記録が、実施時点の plan/procedure version に固定されるか
- ライブ保存ができるか。できないハーネスなら NOT ASSESSED

### 5. 観察・評価・見直し（15）

- 観察履歴を一覧できるか（原則として週に1回以上の履歴。自動違反判定はしない）
- 実施記録 → 観察・フィードバック → 見直しへ戻れるか（Review 材料）
- Review から元の ProcedureRecord / 計画版へ辿れるか
- 歴史的版を最新 Active へ付け替えて表示していないか

### 6. 支援安全性・UX（5）

- fail-closed: 取得失敗・未認証・データ欠損を「問題なし」と出さない
- 未記録・要確認がテキストでも分かるか（色だけにしない）
- 保存中に主要操作を誤って進めさせないか
- 狭い画面で「今の手順」が欠落しないか

## 出力テンプレート

```text
CYCLE
導線: PASS | PARTIAL | FAIL | NOT ASSESSED
永続保存: PASS | NOT ASSESSED | FAIL
週次観察の追跡: PASS | PARTIAL | FAIL | NOT ASSESSED
見直しへの閉ループ: PASS | PARTIAL | FAIL | NOT ASSESSED
P0: なし / あり（ID）

SCORE
in-scope assessed only: xx / 100
excluded: OUT OF SCOPE n, NOT ASSESSED n, NOT SPECIFIED n

その後、6領域の表。
その後、Findings / HOLD / Next Actions。
```

開発判断に直接使える文にする。例:

```text
支援手順→実施結果の導線は PASS。
ただし永続保存は NOT ASSESSED。
週次観察→見直しへの閉ループは NOT ASSESSED。
```

国保連・家族ポータル・身体拘束・バックアップ UI の欠如から
「生活介護の支援サイクルを安全に継続できない」へ飛ばない。
