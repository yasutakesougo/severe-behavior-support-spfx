# implementation-plan

## 目的

設計済みの内容を、着手可能な Issue、PR、テスト、HOLD 条件へ分割します。

実装範囲と対象外を先に固定し、AI が独自判断で工程を省略しない状態を作ります。

## 使用する場面

- 実装 Issue を起票する前
- 要件、DEC、設計が揃った直後
- 変更が大きく、PR 分割が必要なとき

## 入力

- 対象リポジトリ
- 対象 Issue またはドラフト
- 要件定義
- DEC / ADR
- 設計文書
- Contracts の前提
- 制約
- 依存関係
- 既知の HOLD

## 前提条件

- 要件の正本が参照できる
- 設計の正本が参照できる
- 未決 DEC の有無を確認できる
- 対象外を明示できる

## 実行手順

1. 正本資料を列挙する
2. 実装目的を 1 文で固定する
3. 対象範囲と対象外を分離する
4. 変更対象ファイル群またはコンポーネント群を整理する
5. Issue 分割案を作る
6. PR 分割案を作る
7. 実装順序を決める
8. テスト計画を列挙する
9. リスクと HOLD 条件を記録する
10. 完了条件を明文化する

## 確認項目

- 実装目的が単一か
- 対象範囲が過大でないか
- 対象外が明示されているか
- Issue 単位でレビュー可能か
- PR 単位で巻き戻し可能か
- テスト計画が受入条件と対応しているか
- HOLD 条件が先送りではなく停止条件として書かれているか

## 停止条件

- 要件の正本が見つからない
- 未決 DEC が実装をブロックしている
- 対象範囲と対象外を分離できない
- テスト計画へ落とせない受入条件がある
- 人の承認が必要な操作を前提にしている

## 判定基準

- `PASS`: この Skill では原則使用しない。Gate 通過判定が必要な場合は後続 Skill で扱う
- `READY`: 実装目的、対象範囲、Issue 分割、PR 分割、テスト計画、HOLD 条件、完了条件が揃っている
- `HOLD`: 情報不足、承認待ち、未決事項により分割案を固定できない
- `FAIL`: P0 または P1 相当のブロッカーがあり、実装計画を作れない
- `NOT APPLICABLE`: 実装を伴わない相談であり、Issue / PR 分割が不要

## 成果物

- 実装目的
- 対象範囲
- 対象外
- 前提条件
- 変更対象
- Issue 分割
- PR 分割
- 実装順序
- テスト計画
- リスク
- HOLD 条件
- 完了条件

## 禁止事項

- 要件不足を推測で補うこと
- merge、push、deploy を手順に含めること
- SharePoint変更、Microsoft 365変更、Entra ID変更を暗黙前提にすること
- 本番データ変更や物理削除を暗黙前提にすること
- 対象外を未記載のまま進めること
