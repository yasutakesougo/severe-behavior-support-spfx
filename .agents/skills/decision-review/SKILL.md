# decision-review

## 目的

要件に関わる DEC / ADR の不足、未承認、衝突を検出し、設計・実装へ進む前に判断単位を固定します。

## 使用する場面

- requirements-review の直後
- `new-feature` で DEC 確認が必要なとき
- 設計着手前の未決事項棚卸し

## 入力

- 要件レビュー結果
- 既存 DEC / ADR
- 対象 Issue
- 未決と判断されている事項
- 対象外とされている判断

## 前提条件

- 要件の正本または requirements-review 結果を参照できる
- `docs/decisions/` を探索できる
- 判断単位を 1 DEC に混ぜない方針が共有されている

## 実行手順

1. 必要な判断事項を列挙する
2. 既存 DEC / ADR と対応付ける
3. 未作成・未承認の判断を特定する
4. 判断単位の分離（採用 / 再利用 / 配置 / 権限等）を確認する
5. 衝突する決定を検出する
6. 設計・実装をブロックする未決を HOLD 化する
7. 判定を出す

## 確認項目

- 必要な判断が DEC / ADR として識別できるか
- 未承認 DEC が設計・実装をブロックしていないか
- 1 文書に複数判断単位が混在していないか
- 対象外判断が明示されているか
- 既存正本との優先順位が説明できるか

## 停止条件

- ブロッカーとなる未決 DEC がある
- DEC と要件が矛盾している
- 判断単位を分離できない
- 承認証跡が不明

## 判定基準

- `PASS`: この Skill では原則使用しない。Architecture Gate 等は後続で扱う
- `READY`: 必要 DEC / ADR が識別され、未決とブロッカーが明示され、次工程の前提が固定できる
- `HOLD`: 未承認 DEC、情報不足、承認待ちにより設計着手を確定できない
- `FAIL`: P0 または P1 の決定欠陥・衝突があり設計へ進めない。P2 は後続 Issue 可
- `NOT APPLICABLE`: 新規判断を伴わない単純文書修正

## 成果物

- 必要 DEC / ADR 一覧
- 未決一覧
- ブロッカー一覧
- 衝突一覧
- 次工程前提
- Findings（P0 / P1 / P2）

## 禁止事項

- merge、push、deploy を自動実行手順に含めること
- SharePoint変更、Microsoft 365変更、Entra ID変更を承認不要または自動実行として扱うこと
- 本番データ変更や物理削除を許可または手順化すること
- 未確認事項を推測で確定すること
- `HOLD` を `PASS` / `READY` と同義に扱うこと
- 未承認 DEC を承認済みとして扱うこと
- 複数判断単位を 1 DEC にまとめて確定すること
