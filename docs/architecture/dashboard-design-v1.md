この文書は、強度行動障害支援アプリの業務ダッシュボードについて、DESIGN-1〜4の設計境界を固定する。

## 1. この設計が解く問い

現場職員がアプリを開いたときに、今日必要な支援と記録を短時間で把握できることを目標とする。

管理者がアプリを開いたときに、期限、未完了、確認対象を把握できることを目標とする。

分析が必要な場面では、判断対象に対応したグラフだけを表示する。

制度上の事実とアプリ内部の状態を、同じ意味として表示しない。

## 2. 参照する外部デザイン原則

デジタル庁「ダッシュボードデザインの実践ガイドブックとデザインテンプレート」を設計参考にする。

公式ページの最終更新日は2026-07-17である。

同ページは、要件整理、プロトタイプによる合意形成、意思決定や行動に寄与する情報表現、Do's / Don'ts、グリッド、カラーパレットを扱っている。

本アプリではPower BIテンプレートをそのまま移植しない。

本アプリでは、要件整理、行動起点の情報設計、グリッド、意味に基づく色設計の考え方を採用する。

Reference:
https://www.digital.go.jp/resources/dashboard-guidebook

## 3. 現行SHELL-UXから継承する境界

現行`AppShellChrome`の責務を維持する。

現在の主要ナビゲーションは`概要`、`利用者`、`記録`である。

未認証時は業務領域を表示しない。

事業所未選択時は業務領域を表示しない。

主要ナビゲーションが利用不可の状態では、操作可能に見せない。

スキップリンクを維持する。

キーボード操作とフォーカス可視化を維持する。

狭い画面では既存のレスポンシブ境界を尊重する。

今回のDESIGN-1〜4では、これらの挙動を変更しない。

## 4. DESIGN-1 — デザイン原則

### 4.1 行動を先に置く

トップ画面では、利用者に分析を要求する前に、次の行動を提示する。

KPIは数字だけで終わらせず、対象一覧へ到達できる入口として設計する。

### 4.2 情報量より優先順位を固定する

トップ画面に全データを載せない。

最初の画面では、今日の対象、要確認、未記録、期限間近を優先候補とする。

### 4.3 現在有効な支援を先に見せる

利用者詳細では、分析グラフより現在有効な支援内容を先に表示する。

履歴と分析は二次情報として配置する。

### 4.4 色だけで意味を伝えない

状態はテキスト、ラベル、アイコン等と組み合わせて表現する。

赤色を利用者の属性や支援困難度の分類に使用しない。

エラー色はシステム状態または明確な対応必要状態に限定する。

### 4.5 制度上の事実とアプリ状態を分離する

作成者、資格、作成日などの制度・業務上の事実と、保存済み、同期状態などのシステム状態を別領域で表示する。

制度根拠が確認できない独自の承認状態を、制度要件のように表示しない。

### 4.6 アクセシビリティを後付けにしない

キーボードだけで主要操作に到達できることを前提にする。

フォーカス表示を常に可視化する。

状態を色だけに依存させない。

200%表示でも主要情報が欠落しない設計を後続検証対象にする。

## 6. DESIGN-3 — 情報アーキテクチャ

### 6.1 現場向け概要

目的は、今日必要な支援と記録を把握することである。

優先表示候補は次の4項目とする。

- 今日の対象
- 要確認
- 未記録
- 期限間近

主要領域は`今日やること`と`最近の記録`とする。

### 6.2 利用者

利用者一覧から利用者詳細へ遷移する構造を想定する。

利用者詳細の優先順は次とする。

1. 現在有効な支援
2. 支援計画
3. 最近の記録
4. 評価
5. 履歴

### 6.3 記録

記録画面は、入力、未完了確認、最近の記録の3責務に分ける候補とする。

分析グラフを記録入力画面の主目的にしない。

### 6.4 管理・監査

管理者向け画面は、期限、未完了、確認対象、証跡への到達性を中心にする。

管理画面を現場トップと同一レイアウトにしない。

### 6.5 分析

分析画面は必要な問いが定義された場合だけ追加する。

時系列比較には折れ線を優先候補とする。

カテゴリ比較には横棒を優先候補とする。

円グラフは構成比を伝える必然性がある場合だけ候補とする。

### 7.1 KPIカードの挙動

KPIカードは表示専用の飾りにしない。

カードから対応する対象一覧へ到達できる設計を候補とする。

例として`要確認 3件`を選択した場合は、要確認対象3件を絞り込んだ一覧を表示する。

この遷移仕様は本docs-only sliceでは実装しない。

### 7.2 今日やること

各行は、対象、理由、次の操作を1組として表示する。

1行内に複数の競合する主要操作を置かない。

緊急性と重要度を色だけで表現しない。

### 7.3 最近の記録

最近の記録は最新順を基本候補とする。

記録本文をトップ画面へ大量表示しない。

対象と時刻と記録種別から詳細へ到達できる構造を候補とする。

## 11. PC・狭幅表示

PC表示を第一候補とする。

狭幅では情報を単純縮小せず、優先順を維持して縦方向へ再配置する。

KPIカードは狭幅で複数段への折り返しを許可する。

主要操作はタップ対象として十分な高さを確保する。

横スクロールを前提にしない。
